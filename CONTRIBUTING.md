## Project Structure & Module Organization
- frontend/: Create React App. Source in `src/` (`components/`, `pages/`, `hooks/`), tests in `src/__tests__/` or `*.test.tsx`, build output in `build/`.
- backend/: Cloudflare Worker (`worker.js`) and `wrangler.toml` (generated by scripts). Optional `schema.sql` for D1.
- router/, worker/: Reserved if splitting Worker concerns.
- scripts/: Deployment and maintenance scripts (`.sh` + `.ps1`).
- `.env.example`: Required/optional environment variables; copy to a local, non-tracked file for development.

## Build, Test, and Development Commands
- Deploy (Linux/macOS):
  ```
  export CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... CF_PAGES_PROJECT=... REACT_APP_API_ORIGIN=... && bash scripts/deploy_cloudflare.sh
  ```
- Deploy (Windows):
  - Set env vars, then:
  ```
  powershell -ExecutionPolicy Bypass -File scripts/deploy_cloudflare.ps1
  ```
- Verify Cloudflare stack:
  ```
  bash scripts/verify_stack.sh
  ```
  (checks Wrangler version, D1 DBs, Pages projects)
- Local frontend:
  ```
  cd frontend && npm install && npm start
  ```
- Local Worker:
  ```
  cd backend && wrangler dev
  ```
- Seed D1:
  ```
  bash scripts/seed_d1.sh
  ```
  or
  ```
  powershell -ExecutionPolicy Bypass -File scripts/seed_d1.ps1
  ```
  Use `D1_LOCAL=1` for local SQLite.

## Coding Style & Naming Conventions
- Language: JavaScript/TypeScript (CRA defaults); Cloudflare Worker JS for backend.
- Indentation: 2 spaces; prefer single quotes; consistent semicolons.
- Naming:
  - Components: PascalCase (e.g., `ImageGrid.tsx`)
  - Hooks/utilities: camelCase (e.g., `useImages.ts`)
- Tools:
  - Prettier + ESLint are used in `frontend/`.
  - Format: `cd frontend && npx prettier --write "src/**/*.{js,jsx,ts,tsx,json,css,md}"`
  - Lint: `npx eslint "src/**/*.{js,jsx,ts,tsx}"`

## Testing Guidelines
- Frameworks: Jest + React Testing Library for frontend.
- Scope: Smoke coverage for pages and critical utilities; keep tests deterministic and fast.
- Naming: `*.test.tsx` or `*.test.ts`.
- Run tests:
  ```
  cd frontend && npm test
  ```

## Commit & Pull Request Guidelines
- Commits: Follow Conventional Commits, e.g.:
  - `feat: add image search grid`
  - `fix: handle empty D1 response`
- Keep commits small and messages in the imperative mood.
- Pull Requests:
  - Include purpose and linked issue (if any).
  - Include screenshots for UI changes.
  - Add deployment notes (required env vars, routes).
  - Ensure deploy and verify scripts still run.

## Security & Configuration Tips
- Never commit secrets. Use `.env.example` as a template and keep real secrets in non-tracked files.
- Required env vars (examples):
  - `CLOUDFLARE_API_TOKEN`
  - `CLOUDFLARE_ACCOUNT_ID`
  - `CF_PAGES_PROJECT`
  - `REACT_APP_API_ORIGIN`
- Optional env vars:
  - `CF_PAGES_DOMAIN`, `WORKER_ROUTE_PATTERN`, `D1_DB_NAME`, `R2_BUCKET`, `KV_NAMESPACE_ID`/`KV_PREVIEW_ID`, `ADMIN_TOKEN`
- Admin endpoints:
  - When `ADMIN_TOKEN` is set, write endpoints require `Authorization: Bearer <token>`.
  - In production set via: `wrangler secret put ADMIN_TOKEN`.
- Dev convenience:
  - `frontend/.env.development.local` can contain:
    ```
    REACT_APP_API_ORIGIN=http://127.0.0.1:8787
    REACT_APP_ADMIN_TOKEN=<optional>
    ```

## Feature flags
- Bind KV as `KV` (via `wrangler kv namespace create` and `[[kv_namespaces]]` in `backend/wrangler.toml`).
- Frontend reads flags at boot and caches `flags.json`.
- Admin flags UI available at `/admin/flags` (requires `ADMIN_TOKEN`).
